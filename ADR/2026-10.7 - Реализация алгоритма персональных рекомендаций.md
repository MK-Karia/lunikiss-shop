# 2026-10.7 - Реализация алгоритма персональных рекомендаций
*Дата:* 27 октября 2026 г.
*Статус:* Принято
*Команда:*
- Кузовкова Мария
- Николаева Любовь
- Соловьева Ксения
## Контекст 
Требование FR-03 указывает, что система должна рассчитывать и отображать персональные рекомендации на основе контентной фильтрации (векторное представление атрибутов товара и профиля пользователя), а при отсутствии истории - выводить товары с наилучшим рейтингом. Требование FR-67 регламентирует возможность конфигурирования параметров рекомендаций администратором
## Рассмотренные варианты
- Сторонняя тяжелая ML-платформа (например, AWS Personalize / SaaS)
- Векторный поиск внутри баз данных (pgvector для PostgreSQL) с оффлайн/асинхронным пересчетом ембеддингов
- Простая фильтрация на основе совпадения тегов (без векторов)
## Решение
- Выбран Векторный поиск на базе pgvector (расширение PostgreSQL) с формированием векторных эмбеддингов товаров и профилей пользователей через фоновые задачи (Background Workers)
## Обоснование
- Экономия бюджета (LIM-15): Расширение pgvector бесплатно, работает в той же БД PostgreSQL и не требует аренды специализированных дорогостоящих векторных БД (Pinecone/Qdrant) или отдельных серверов GPU
- Холодный старт: Автоматическое переключение на топ по рейтингу (FR-03) при отсутствии векторов у нового пользователя
- Настраиваемость (FR-67): Администратор в административной панели может изменять настройки рекомендаций
## Недостатки решения
По мере роста каталога векторный поиск по косинусному расстоянию требует создания HNSW/IVFFlat индексов в PostgreSQL
## Последствия
- В PostgreSQL активируется расширение pgvector
- Эмбеддинги карточек рассчитываются при их создании/редактировании продавцом
- Эмбеддинг пользователя обновляется в фоновом режиме при оформлении заказов или добавлении в избранное
