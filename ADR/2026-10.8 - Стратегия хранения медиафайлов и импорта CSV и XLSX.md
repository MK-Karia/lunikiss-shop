# 2026-10.8 - Стратегия хранения медиафайлов и импорта CSV и XLSX
*Дата:* 27 октября 2026 г.  
*Статус:* Принято  
*Команда:*
- Кузовкова Мария
- Николаева Любовь
- Соловьева Ксения
## Контекст 
В соответствии с ограничениями:
- фото и видео не более 5 Мб (LIM-09), не более 4 фото (LIM-10), не более 1 видео (LIM-11) на карточку
- поддержка файлов лишь формата CSV и XLSX (LIM-12) с размером не более 10 Мб (LIM-13)
## Рассмотренные варианты
- Сохранение медиафайлов в виде BLOB непосредственно в базе данных PostgreSQL
- Загрузка файлов на бэкенд и сохранение на локальный диск сервера
- Облачное S3-совместимое хранилище (S3 Object Storage) с обработкой на API Gateway / Edge
- HTTP-кэширование в браузере и на уровне Reverse Proxy (Nginx)
## Решение
Выбран комбинированный подход: объектное хранилище S3 (S3 Compatible Storage) с валидацией размера и типа файлов на Nginx / API Gateway и асинхронной обработкой импорта SKU через фоновые очереди задач и HTTP-кэширование в браузере и на уровне Reverse Proxy (Nginx)
## Обоснование
- Соблюдение NFR и LIM: Валидация ограничений по размеру (client_max_body_size 10m) выполняется на уровне Reverse Proxy (Nginx) до попадания запроса в backend, экономится память бэкенда
- Разгрузка БД: Медиафайлы (фото до 4 шт, видео до 1 шт) хранятся в S3, в БД сохраняются только ссылки (URL)
- Асинхронная обработка CSV/XLSX (LIM-12): Загруженный файл импорта пишется во временный S3-буфер, после чего Worker поэтапно считывает SKU и обновляет остатки, гарантируя отклики системы без зависаний UI
- Ускоренная отдача файлов: Браузер пользователя загружает изображения ровно один раз, далее беря их из локального кэша
## Недостатки решения
Необходимость подключения S3-провайдера (например, Yandex Object Storage)
## Последствия
- Реализуется сервис MediaStorageService для работы с S3 API
- Реализуются парсеры CSV/XLSX с ограничением по объему обрабатываемых строк
